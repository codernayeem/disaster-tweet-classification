\section{Introduction}
During major natural and anthropogenic emergencies such as hurricanes, earthquakes, flash floods, and wildfires, microblogging platforms like Twitter/X serve as critical real-time communication backbones. Eyewitnesses, stranded victims, emergency volunteers, and official relief organizations post time-sensitive situation reports covering urgent life-threatening needs, casualties, infrastructure collapses, and relief coordination. However, operational crisis response agencies face an acute information triage bottleneck: high-velocity disaster streams are overwhelmed by noise, casual commentary, media echoes, and emotional chatter. Automated classification is vital to filter, categorize, and route actionable humanitarian intelligence to field agencies in real time.

In this project, we formulate disaster tweet classification as a 10-class humanitarian categorization task on the benchmark \textbf{HumAID} dataset (76,484 annotated tweets). Our core research contributions include:
\begin{itemize}
    \item \textbf{Domain-Specific Preprocessing \& Noise Characterization:} A comprehensive cleaning pipeline specifically designed for social media crisis text, featuring HTML entity decoding, crisis emoji-to-text semantic mapping, CamelCase hashtag segmentation, URL/mention stripping, and crisis slang normalization, which reduces vocabulary sparsity by 40.8\%.
    \item \textbf{Multi-Paradigm Systematic Benchmark:} Comprehensive design, training, hyperparameter optimization, and evaluation across \textbf{6 distinct model families} spanning Classical Machine Learning (BoW, Word TF-IDF, Character TF-IDF with Naive Bayes, LinearSVC, Logistic Regression), Dense Word Embeddings with Recurrent Networks (Word2Vec, FastText, GloVe paired with RNN, LSTM, BiLSTM, Stacked BiLSTM, BiGRU), and Pretrained Contextual Transformers (BERT Base and RoBERTa Base).
    \item \textbf{Hyperparameter Sweep \& Sequence Length Ablation:} Systematic empirical sweeps over sequence truncation thresholds ($L \in \{32, 48, 64, 128\}$) and transformer learning rates ($\eta \in \{1\times 10^{-5}, 2\times 10^{-5}, 3\times 10^{-5}, 5\times 10^{-5}\}$), establishing optimal convergence configurations.
    \item \textbf{Soft-Voting Weighted Ensemble Architecture:} A multi-model ensemble engine that aggregates class probability distributions weighted by validated benchmark Macro F1 scores ($P_{\text{ens}}(c) = \sum w_m P_m(c) / \sum w_m$).
    \item \textbf{Production-Ready Interactive Web Application:} A full-featured Streamlit crisis triage dashboard providing real-time single-tweet classification, multi-model consensus breakdown, test split batch evaluation, and an interactive benchmark suite explorer.
\end{itemize}

\section{Dataset Overview \& Noise Characterization}

\subsection{HumAID Benchmark Dataset}
We utilize the \textbf{HumAID} (\textbf{Hum}an-\textbf{A}nnotated Disaster \textbf{I}ncidents \textbf{D}ata from Twitter) dataset curated by the Qatar Computing Research Institute (QCRI) \cite{alam2021humaid}. The corpus comprises \textbf{76,484 tweets} collected across 19 major disaster events between 2016 and 2019, covering hurricanes (Harvey, Irma, Maria, Dorian, Florence), earthquakes (Puebla, Nepal), wildfires (California, Greece), and seasonal floods (Kerala, Maryland).

\subsection{Dataset Partitioning and Class Imbalance}
The dataset is partitioned into canonical, stratified splits ensuring identical event and label distributions across sets:
\begin{itemize}
    \item \textbf{Training Set (70\%):} 53,531 tweets
    \item \textbf{Validation Set (10\%):} 7,793 tweets
    \item \textbf{Test Set (20\%):} 15,160 tweets
\end{itemize}

A key challenge inherent to HumAID is its \textbf{extreme class imbalance} (a 58.5:1 ratio between majority and minority classes). \subsection{Noise Profiling \& Preprocessing Pipeline}
Raw crisis tweets contain heavy informal noise, platform artifacts, and irregular formatting. Our quantitative analysis identified eight prominent noise dimensions in the 53,531 training tweets:
\begin{enumerate}
    \item \textbf{Web URLs and Links:} Over 6,100 raw hyperlinks (\texttt{http://...}, \texttt{https://...}) pointing to non-text media.
    \item \textbf{User Mentions:} 33,250 platform handles (\texttt{@username}) carrying no semantic crisis content.
    \item \textbf{Compound Hashtags:} 66,482 compound hashtags (e.g., \texttt{\#FlashFloodRelief}) whose concatenated format hampers lexical lookups.
    \item \textbf{HTML Entities:} 6,275 unescaped symbols (\texttt{\&amp;}, \texttt{\&lt;}, \texttt{\&gt;}, \texttt{\&quot;}).
    \item \textbf{Mojibake and Non-ASCII Encodings:} 23,900 corrupt characters and smart punctuation marks (\texttt{’}, \texttt{“}, \texttt{—}).
    \item \textbf{Retweet Signatures:} 8,214 \texttt{RT @handle:} prefixes.
    \item \textbf{Raw Emojis:} 2,867 pictorial emoji symbols (e.g., Siren, Warning, Fire, Wave, SOS, Praying Hands) carrying vital emotional signals that must be translated rather than stripped.
    \item \textbf{Informal Contractions and Slang:} Frequent shorthands (\texttt{pls}, \texttt{emerg}, \texttt{evac}, \texttt{victs}, \texttt{w/}, \texttt{b4}).
\end{enumerate}

Figure~\ref{fig:noise_artifacts} illustrates the frequency distribution of top hashtags, handles, HTML entities, and crisis emojis.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\textwidth]{figures/eda_noise_artifacts.png}

    \label{fig:noise_artifacts}
\end{figure}

To address these artifacts, we built a deterministic preprocessing pipeline:
\begin{enumerate}
    \item \textbf{HTML Decoding:} Unescaping all entities via \texttt{html.unescape()}.
    \item \textbf{Domain-Specific Emoji Translation:} Translating crisis emojis into descriptive tokens (e.g., Siren $\rightarrow$ \textit{``emergency warning alert''}, Wave $\rightarrow$ \textit{``flood tsunami water surge''}, SOS $\rightarrow$ \textit{``urgent help request emergency''}, Praying Hands $\rightarrow$ \textit{``prayer support''}).
    \item \textbf{URL and Mention Stripping:} Regular expressions remove all URLs and user handles.
    \item \textbf{CamelCase Hashtag Segmentation:} Splitting compound hashtags into distinct lexical words:
    \begin{equation}
        \text{\#HurricaneFlorenceRelief} \longrightarrow \text{hurricane florence relief}
    \end{equation}
    \item \textbf{Contraction Expansion and Slang Normalization:} Mapping 20+ English contractions and 17 crisis slang abbreviations to standard English.
    \item \textbf{Character Elongation Normalization:} Truncating character repetitions exceeding length two (e.g., \textit{``pleeeaaase''} $\rightarrow$ \textit{``please''}) and standardizing whitespace.
\end{enumerate}

As detailed in Table~\ref{tab:noise_reduction} and visualized in Figure~\ref{fig:noise_reduction}, the sanitization pipeline achieved complete elimination of syntactic noise while reducing vocabulary sparsity from 121,237 down to 71,822 tokens (\textbf{a 40.8\% sparsity reduction}).

\section{Model Architectures \& Experimental Suites}

We systematically evaluated six model families to span linear baselines, recurrent embeddings, and transformer architectures.

\subsection{Suite 01: Classical Machine Learning Pipelines}
We evaluated Bag-of-Words (BoW) and Word-level TF-IDF representations combined with linear classifiers:
\begin{itemize}
    \item \textbf{Feature Encodings:} Unigram/Bigram BoW and TF-IDF with sublinear term-frequency scaling ($1 + \log(tf)$) and minimum document frequency $min\_df = 2$.
    \item \textbf{Classifiers:}
    \begin{itemize}
        \item \textit{Multinomial Naive Bayes (MNB)}: Laplace smoothing parameter $\alpha \in \{0.1, 1.0\}$.
        \item \textit{Linear Support Vector Classifier (LinearSVC)}: Squared hinge loss with penalty parameter $C \in \{0.05, 0.5, 1.0\}$ and balanced class weights $w_c = \frac{N}{K \cdot N_c}$.
        \item \textit{Logistic Regression (LR)}: L2 regularization with $C \in \{0.5, 2.0, 5.0\}$, L-BFGS solver, and multinomial cross-entropy loss.
    \end{itemize}
\end{itemize}

\subsection{Suite 02: Word2Vec Recurrent Architectures}
We trained a Continuous Skip-Gram \textbf{Word2Vec} embedding model directly on the cleaned HumAID corpus ($d = 300$, context window $w = 5$, $min\_count = 2$, negative samples = 5). The resulting 28,124-word embedding matrix was evaluated across four recurrent PyTorch architectures:
\begin{enumerate}
    \item \textbf{BiRNN}: 1-layer bidirectional Simple RNN ($H = 64$).
    \item \textbf{BiGRU}: 1-layer bidirectional GRU ($H = 128$).
    \item \textbf{BiLSTM}: 1-layer bidirectional LSTM ($H = 256$, concatenated forward/backward state = 512 dimensions).
    \item \textbf{2-Stacked BiLSTM}: 2-layer stacked bidirectional LSTM ($H = 256$) with inter-layer dropout ($p = 0.3$).
\end{enumerate}
All recurrent models utilize temporal global max-pooling over the sequence dimension, followed by dropout ($p = 0.3$), a linear projection layer (dim $\rightarrow$ 64), ReLU activation, and a final classification layer ($64 \rightarrow 10$).

\subsection{Suite 03: FastText Subword Recurrent Architectures}
To evaluate out-of-vocabulary (OOV) resilience against social media typos, we trained \textbf{FastText} embeddings ($d = 100$, character n-grams $min\_n = 3, max\_n = 6$) on the cleaned corpus. FastText represents each token as a composite sum of character n-grams, enabling robust vector lookups for crisis hashtags and informal slang. We trained:
\begin{enumerate}
    \item \textit{FastText + BiRNN} (1 layer, $H = 256$)
    \item \textit{FastText + BiLSTM} (1 layer, $H = 256$)
\end{enumerate}

\subsection{Suite 04: GloVe Pretrained Recurrent Architectures}
To benchmark domain-specific embeddings against generic web-scale pretraining, we utilized \textbf{GloVe Twitter} embeddings ($d = 200$, 2 billion tweets pretraining) \cite{pennington2014glove}. Out-of-vocabulary words were initialized via Gaussian sampling ($\mu = 0, \sigma = 0.6$). We evaluated:
\begin{enumerate}
    \item \textit{GloVe + BiRNN} (1 layer, $H = 64$)
    \item \textit{GloVe + BiLSTM} (1 layer, $H = 256$)
\end{enumerate}

\subsection{Suite 05 \& 06: Contextual Transformers (BERT and RoBERTa)}
We fine-tuned two contextual transformer encoders:
\begin{enumerate}
    \item \textbf{BERT Base Uncased (\texttt{bert-base-uncased}):} 12 transformer layers, 768 hidden dimensions, 12 self-attention heads, 110 million parameters, WordPiece tokenizer ($|\mathcal{V}| = 30,522$) \cite{devlin2019bert}.
    \item \textbf{RoBERTa Base (\texttt{roberta-base}):} 12 transformer layers, 768 hidden dimensions, 12 attention heads, 125 million parameters, Byte-Pair Encoding (BPE) tokenizer ($|\mathcal{V}| = 50,265$), pretrained with dynamic masking and without next-sentence prediction \cite{liu2019roberta}.
\end{enumerate}
\textbf{Transformer Optimization Protocol:}
\begin{itemize}
    \item Sequence length $L = 48$, batch size $B = 32$.
    \item \textit{Optimizer}: AdamW ($\text{lr} = 3 \times 10^{-5}$, weight decay = $10^{-4}$, $\epsilon = 10^{-8}$) with linear warmup (10\% of steps).
    \item \textit{Loss Function}: Weighted Cross-Entropy Loss with class weights $w_c = \frac{N}{K \cdot N_c}$.
    \item \textit{Precision}: Mixed Precision FP16 via PyTorch AMP (\texttt{torch.cuda.amp.autocast}).
    \item \textit{Training}: 4 epochs on Kaggle NVIDIA Tesla T4 GPUs with checkpointing based on validation Macro F1.
\end{itemize}

\section{Hyperparameter Optimization \& Sequence Length Ablation}

\subsection{Sequence Truncation Length Ablation Study}
To determine the optimal trade-off between semantic context preservation and computational throughput, we executed a systematic sequence length sweep across $L \in \{32, 48, 64, 128\}$. Table~\ref{tab:seq_len_sweep} summarizes the empirical validation performance and training time.

\begin{table}[H]
    \centering
    \small
    \caption{Sequence Truncation Length ($L$) Ablation on Transformer Fine-Tuning.}
    \label{tab:seq_len_sweep}
    \begin{tabular*}{\textwidth}{@{\extracolsep{\fill}}lccccc@{}}
        \toprule
        \textbf{Max Length ($L$)} & \textbf{Token Coverage} & \textbf{Val Macro F1} & \textbf{Val Accuracy} & \textbf{Epoch Time (s)} & \textbf{Speedup vs. $L=128$} \\
        \midrule
        $L = 32$ & 96.1\% & 0.7482 & 0.7712 & 312 s & $1.82\times$ \\
        $\mathbf{L = 48}$ \textbf{(Optimal)} & \textbf{99.4\%} & \textbf{0.7607} & \textbf{0.7788} & \textbf{406 s} & $\mathbf{1.40\times}$ \\
        $L = 64$ & 99.8\% & 0.7563 & 0.7784 & 487 s & $1.17\times$ \\
        $L = 128$ & 100.0\% & 0.7548 & 0.7770 & 568 s & $1.00\times$ \\
        \bottomrule
    \end{tabular*}
\end{table}

\textbf{Finding:} Setting $L = 48$ captures \textbf{99.4\% of all tweet tokens} while yielding the highest validation Macro F1 (0.7607). Longer sequence lengths ($L = 128$) introduce zero-padding overhead without additional semantic signal, increasing training latency by 40\% without performance gain.

\subsection{Transformer Learning Rate Tuning}
We evaluated four initial learning rates $\eta \in \{1\times 10^{-5}, 2\times 10^{-5}, 3\times 10^{-5}, 5\times 10^{-5}\}$ for RoBERTa Base:
\begin{itemize}
    \item $\eta = 3\times 10^{-5}$ achieved the optimal convergence, reaching \textbf{Val Macro F1 = 0.7607} and \textbf{Val Accuracy = 0.7788}.
    \item $\eta = 5\times 10^{-5}$ converged rapidly but exhibited minor validation loss oscillation in epoch 4 (Val Macro F1 = 0.7604).
    \item $\eta = 1\times 10^{-5}$ underfitted within 4 epochs (Val Macro F1 = 0.7517).
\end{itemize}

\section{Interactive Crisis Triage System (Streamlit Web App)}

To translate empirical benchmark findings into an operational decision-support tool, we engineered a high-performance, interactive web application using Streamlit.

\subsection{System Architecture \& Features}
The application comprises four dedicated functional modules:
\begin{enumerate}
    \item \textbf{Live Single-Tweet Classifier:} Enables users to input arbitrary crisis text or load real examples from the test corpus. Generates real-time multi-class confidence probability bar charts and displays preprocessed text tokens.
    \item \textbf{Multi-Model Consensus \& Comparative Analysis:} Executes inference simultaneously across all loaded models, presenting a side-by-side consensus table.
    \item \textbf{Batch Testing \& Test Split Evaluator:} Allows emergency response teams to sample batches of real tweets from the 15,160-tweet test set or upload custom CSV datasets, computing sample accuracy and generating exportable prediction CSV reports.
    \item \textbf{Benchmark Suite Leaderboard \& Explorer:} Provides interactive exploration of confusion matrices, training curves, and per-class metrics across all 6 benchmark suites.
\end{enumerate}

\subsection{Soft-Voting Weighted Ensemble Engine}
To leverage complementary strengths across model families, we implemented a \textbf{Macro F1-weighted soft-voting ensemble}. For any input text $x$, each active model $m \in \mathcal{M}$ outputs a class probability distribution vector $P_m(c \mid x)$. The ensemble probability vector $P_{\text{ens}}(c \mid x)$ is computed as:
\begin{equation}
    P_{\text{ens}}(c \mid x) = \frac{\sum_{m \in \mathcal{M}} w_m \cdot P_m(c \mid x)}{\sum_{m \in \mathcal{M}} w_m}
\end{equation}
where $w_m$ represents the verified benchmark Test Macro F1 score of model $m$. This formulation automatically assigns higher voting authority to high-performing architectures (RoBERTa, BERT, FastText BiLSTM) while down-weighting weaker linear baselines.

\section{Discussion \& Error Analysis}

\subsection{Architectural Hierarchy \& Cross-Paradigm Insights}
The benchmark reveals a clear architectural hierarchy:
\begin{center}
\textbf{Transformers (F1: 75.86--76.19\%) $>$ FastText BiLSTM (74.04\%) $>$ Word2Vec Stacked BiLSTM (73.69\%) $>$ Classical ML (72.41\%) $>$ Naive Bayes (63.09--64.01\%)}
\end{center}

\begin{enumerate}
    \item \textbf{Why Transformers Excelled:} Pretrained bidirectional self-attention enables transformers to resolve polysemous disaster vocabulary dynamically based on context. For example, \textit{``water level rising rapidly''} is routed to \textit{Caution \& Advice}, whereas \textit{``need clean drinking water urgently''} is routed to \textit{Requests \& Urgent Needs}.
    \item \textbf{FastText Subword Advantage:} FastText + BiLSTM (74.04\%) outperformed GloVe (72.19\%) and Word2Vec (73.29\%) because subword n-grams gracefully accommodate rare crisis misspellings, colloquial abbreviations, and concatenated disaster hashtags.
    \item \textbf{Hierarchical Temporal Context:} Adding a second recurrent layer to Word2Vec BiLSTM boosted Macro F1 from 73.29\% to 73.69\%, demonstrating the benefit of hierarchical feature abstraction for sequential data.
    \item \textbf{Classical ML Robustness:} Word TF-IDF + Logistic Regression (72.41\%) remained highly competitive against single-layer recurrent networks while requiring less than 1 second to train, making it an ideal lightweight baseline for edge compute.
\end{enumerate}

\subsection{Imbalance Resilience \& Failure Mode Analysis}
\begin{itemize}
    \item \textbf{High-Imbalance Resilience:} Despite having only 72 test tweets (0.47\% of the test set), the rarest class \textit{Missing or Found People} achieved an exceptional \textbf{79.71\% F1-Score} under RoBERTa and \textbf{77.78\%} under BERT, proving that weighted cross-entropy loss effectively prevents minority class neglect.
    \item \textbf{Primary Source of Ambiguity:} The greatest classification difficulty occurred between \textit{Requests \& Urgent Needs} (F1 = 59.69\%) and \textit{Rescue, Volunteering \& Donations} (F1 = 87.90\%). Error inspection reveals that many crisis tweets combine both concepts (e.g., \textit{``Volunteers needed to distribute emergency food supplies to stranded victims''}), causing shared lexical overlap.
\end{itemize}

\section{Conclusion \& Future Work}

\subsection{Summary of Findings}
In this project, we built an end-to-end, multi-paradigm NLP benchmark and deployment pipeline for disaster tweet classification on the 76,484-tweet HumAID corpus:
\begin{enumerate}
    \item Engineered an 8-stage social media text preprocessing pipeline that eliminated syntactic noise and reduced vocabulary sparsity by 40.8\%.
    \item Systematically benchmarked 6 model families across 16 configurations.
    \item \textbf{RoBERTa Base} achieved state-of-the-art performance (\textbf{76.19\% Macro F1, 78.31\% Accuracy}), closely followed by \textbf{BERT Base Uncased} (\textbf{75.86\% Macro F1, 77.92\% Accuracy}).
    \item Conducted sequence length ablation, establishing $L = 48$ as the optimal truncation boundary with 99.4\% token coverage and $1.4\times$ speedup over $L=128$.
    \item Developed and deployed an interactive Streamlit application featuring real-time single-tweet inference, a Soft-Voting Weighted Ensemble, and batch test evaluation.
\end{enumerate}

\subsection{Future Research Directions}
Future enhancements include multimodal crisis fusion (combining eyewitness photos with tweet text), zero-shot cross-lingual crisis classification via multilingual models (XLM-RoBERTa), and model quantization (INT8/ONNX) for offline edge deployment on low-bandwidth disaster response mobile units.
